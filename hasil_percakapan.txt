2. RINGKASAN ANALISIS BLUEPRINT MENUJU PRODUKSI
--------------------------------------------------------------------------------
A. Penilaian Dokumen Blueprint
- Kualitas: Sangat matang, terstruktur, konsisten.
- Skema Pemetaan: 1:1 antara Functional Requirements, Modul Aplikasi, Skema Database (ERD/DDL), REST API Endpoints, dan Diagram UML (Use Case, Activity, Sequence, Class, State).
- Pendekatan Moduler: MVP -> Portfolio+ -> IoT Dasar -> IoT Lanjutan mencegah overengineering.

B. Komponen Arsitektur Inti
- Database:
  * Soft delete (deleted_at) pada entitas users, components, devices.
  * Append-only untuk audit trail: component_stock_history, sensor_readings, audit_logs.
  * DB Check constraints: stock_available <= stock_total, dsb.
- Keamanan:
  * Pemisahan otentikasi Web (JWT Access Token & Refresh Token) dan IoT Device (API Key unik per-device dengan hash api_key_hash).
  * Role-Based Access Control (RBAC): Admin vs Mahasiswa/User.
- PWA & IoT:
  * HTTP REST JSON memudahkan komunikasi ESP32 tanpa overhead broker MQTT di awal.
  * PWA dengan Workbox caching: CacheFirst untuk aset statis, NetworkFirst untuk data API.

C. Aspek Kesiapan Tahap Produksi (Production Readiness)
1. Hosting & Infrastruktur:
   - Frontend: Vercel / Netlify (SSL otomatis, CDN global).
   - Backend: Render / Railway / Koyeb / VPS (waspadai cold start pada free tier, gunakan keep-alive atau dedicated tier).
   - Database: Supabase / Neon PostgreSQL dengan PgBouncer (Port 6543) untuk connection pooling.
   - Media Storage: Cloudinary / Supabase Storage untuk foto komponen/user (menghindari kehilangan data akibat disk ephemeral).
2. Gap & Solusi Operasional:
   - Pengendalian bloat sensor_readings melalui interval wajar dan retention policy/cron cleanup.
   - Background jobs untuk status offline device dan loan overdue di-trigger via external cron scheduler / webhook terproteksi.
   - Proteksi rate limit pada endpoint device /api/sensors/readings dan /api/devices/heartbeat.
   - Enforce HTTPS menyeluruh, termasuk library HTTPClient ESP32.
